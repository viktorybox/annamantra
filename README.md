# Anna Mantra

Astro, TypeScript, статическая сборка. Node.js 24 (минимум 22.12).

```sh
npm ci
npm run dev -- --host 0.0.0.0
npm run check
npm run build
npm run check:site
```

## Содержимое

- `src/data/site.ts`, `src/data/home-content.ts` — исходные тексты RU/FR.
- `src/data/faq.ts` — FAQ, редактируется в коде; в Sanity его нет.
- `src/data/quiz.ts` — одноразовый квиз. Публичный квиз доступен на русском.
- `src/content/blog/` — публикации до подключения CMS. После подключения проекта источником блога становится Sanity; удалённая в CMS статья не появляется заново из локального файла.
- `public/images/` — изображения сайта. `inbox/` используется только как исходный материал.
- Шрифт Manrope хранится в `public/fonts/manrope/` под SIL OFL 1.1; лицензия находится рядом с файлами.

## Ссылки, цена и домен

Скопировать `.env.example` в `.env` и заполнить только подтверждённые значения. Пока ссылки отсутствуют, кнопки записи и канала недоступны и не имитируют действие. После создания документа настроек в Sanity он становится источником ссылок и цены; удаление ссылки в CMS отключает соответствующую кнопку.

`PUBLIC_SITE_URL` — настоящий HTTPS-домен без пути. До его указания страницы и robots закрыты от индексации. После указания сборка создаёт canonical, hreflang, Open Graph и sitemap с настоящими адресами.

## Sanity

1. Создать проект и публичный dataset `production` под аккаунтом Анны.
2. В `studio/.env` указать `SANITY_STUDIO_PROJECT_ID` и `SANITY_STUDIO_DATASET` по образцу `studio/.env.example`.
3. Выполнить `npm ci --prefix studio`, затем `npm run dev --prefix studio`.
4. В корневом `.env` указать тот же project ID и dataset в переменных `PUBLIC_SANITY_*`.
5. Создать документы текстов главной для RU и FR, настройки, статьи, даты и разрешённые отзывы. Перед включением CMS перенести текущую опубликованную статью в Sanity.
6. Разместить Studio через `npm run deploy --prefix studio` после выбора проекта и адреса админки.

Пароль и токены не добавляются в репозиторий. Для публичного чтения статической сборке токен не нужен. Один аккаунт владельца, FAQ и квиз остаются в коде.

В Sanity подготовлены: выбранные тексты главной, портрет, расписание, отзывы с подтверждением разрешения, статьи, ссылки, цена и email. Черновики не попадают в публичную сборку. Будущая дата статьи не публикуется раньше времени, но для её появления нужна новая сборка. Видеоотзывы загружаются только по запросу пользователя.

## Публикация

`dist/` — готовый статический сайт для Surge или другого статического хостинга. Содержимое Sanity читается во время сборки. Если настроенный CMS недоступен или вернул некорректные данные, сборка завершается ошибкой: опубликованная версия сайта должна сохраняться.

В `.github/workflows/check.yml` подготовлены проверки сборки. Автоматический деплой и webhook подключаются после получения репозитория, домена и выбранного способа публикации. Секреты хостинга хранятся в настройках GitHub Actions, а не в файлах проекта.

Перед запуском нужны реальные ссылки, цена, контакты, юридические тексты, разрешённые отзывы, проект Sanity, репозиторий и домен. Текущий список состояния — `docs/implementation-audit.md`.
